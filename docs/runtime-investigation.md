# Runtime investigation

The current runtime is Cactus 4.1.4 with Needle 3 weights, as pinned by the official `cactus-compute` 4.2.7 release. The exact release tag, native ABI signatures, artifact digests, and platform paths are recorded in [the upstream assessment](needle3-upstream.md). The former Needle 2.0.3 implementation is preserved in the repository's history at commit `1920988115203a3b7d048dac9d35e00d8f265f95`.

Cactus 4 exposes process-global functions for model load, session initialization, completion, reset, thread configuration, and diagnostics. The wrapper binds the six required functions with source-generated C calling conventions, checks the exports before selecting an engine, and holds one process-wide lease for the lifetime of the session. A second client can share the same engine identity. Changing engine or model identity requires another process.

The shared engine consumes NUL-terminated UTF-8 strings and writes a NUL-terminated JSON envelope into a caller-sized buffer. Negative return values are native failures. A non-negative completion return value is independent of JSON length. When the engine returns a failure envelope with a non-negative status, its error, code, and reason are available on the compilation. A negative status throws `NeedleInferenceException` with the available native diagnostic.

On Windows x64, the pinned model produced an ordinary call, an empty proposal, suppressed calls for missing arguments, and a proposed weather call accompanied by `validation.negation = true` for an explicit prohibition. The managed policy withholds negated calls. It preserves native suppressions separately and rejects unknown tools or arguments that fail verification against the declared schema. A successful native envelope can still yield a suppressed, failed, or low-confidence managed outcome.

The wrapper implements tool argument verification and source-generated typed extraction over a single valid extraction call. The pinned Python package also adds date facts, tracks date grounding across turns, repairs selected arguments, and applies extra extraction-specific source checks. .NET exposes native validation metadata and supports caller-supplied system facts. Full Python grounding and repair parity is outside this integration.
